## 采集→开发转换原则

1. **项目不允许长期停留在资料采集状态**——采集是手段，开发是目的
2. **评估先行**：资料足够支撑开发 → 立即转入开发；不足 → 缺口具体化（缺什么/怎么补/多久补齐）
3. **评估落盘**：就绪度评估表存档，已通过项目不重复评估直接进开发
4. 评估分级：T1 立即开发 / T2 资料足待拍板 / T3 继续采集或先补验证

## 七步开发方法论

```
深入调研 → 竞品分析 → 数据采集 → 用户画像 → 功能设计 → 前端设计 → 商业变现
```

- 七步顺序推进，每步有产出物
- 已有资产直接盘点复用（引用文件路径），不重做
- 启动开发 = 产出《项目开发启动书》：七步盘点 + 任务分解 + 里程碑 + 资源需求
- 知识付费类项目：⑤功能设计→交付物结构、⑥前端设计→商品页/交付形态，方法论适配不削足适履

## 研究型项目五模架构

```
看（资讯锁客）→ 学（边教边卖）→ 试（¥0-99）→ 干（¥99-999）→ 精（¥999+）
```

- **盈利双引擎**：资讯锁客（看→学→试）+ 边教边卖（学→试→干→精）
- 每个"研-"项目必须有 `00-五模架构.md`（映射表/缺口清单/盈利链路/下一步 3 动作）
- 看/学层每篇内容尾部带下一层转化钩子
- 内部支撑型模块如实标"内部不对外"，不硬凑
- 价格档位参考：试 ¥0-99｜干 ¥99-999｜精 ¥999+

## 开发状态纪律

- 开发中项目每周必须有可验证产出（代码/售卖件/上线物）
- 停滞超 2 周的项目自动降级回评估（检查是否缺资源未拍板）
- 调研报告不是开发产出——只有转化件（上架 SKU/可跑工作流/交付包）才算
