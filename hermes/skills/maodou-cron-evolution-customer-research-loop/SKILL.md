# 毛豆 cron auto-evolve 客户研究 → 决策包证据回收模式

> 📅 2026-09-07 08:00 实证（毛豆 cron auto-evolve 第 5 次今日触发）
> 📌 关联 evolution 报告：`~/.hermes/profiles/maodou/evolution/2026-09-07_08.md`
> 🔗 关联决策包：`evolution/***SECRET***.md`（P0 #21）
> 🔗 关联 SOP：`lookforge-种子客户开发SOP_v0.1_2026-09-06.md` §七"下个 cron"承诺

## 一、模式定义（一句话）

**不要在 cron 自进化时段做泛泛行业调研。承接最近一份 SOP/决策包承诺的下一步专项任务，用真实公开数据（爱企查/官网/web_search/政府采购平台）拿到可验证证据，把发现反哺回决策包，强化催办理由。**

## 二、5 步标准流程

### Step 1：读最近 1-2 份 evolution 报告
- `ls -lt ~/.hermes/profiles/maodou/evolution/ | head -5`
- 找"下一步 / 下个 cron / 承诺 / 待办"关键词
- 找出**最具体的下一步动作**（不是"做行业调研"这种泛词，而是"5 家候选客户扩展画像"这种专项任务）

### Step 2：识别承接关系
- 新动作 → 上游 SOP 哪一段？
- 新动作 → 哪份决策包能受益？
- 预期产出（具体到文件名）是什么？

### Step 3：用 web_search + 爱企查 + 官网做调研
**优先级**（按权威性）：
1. **爱企查/天眼查** → 工商信息（注册资本/股东/专利）
2. **公司官网** → 主营业务/产品线/联系人
3. **政府采购平台（tgnet.com / 千里马招标网）** → 招投标/项目
4. **行业媒体/KOL 推荐位（knozall 等）** → 行业地位
5. **web_search 普通结果** → 弱证据，仅辅助

**每条信息必须带来源 URL**（华哥偏好）。

### Step 4：交叉验证 + 优先排序
- 同名企业（如"海容工业"在山东做民宿/在四川做种养殖）→ **标注"待核实"**，不强行匹配
- 信息冲突 → 取权威源（爱企查 > 官网 > 新闻 > SEO 农场）
- 排序维度：业务匹配度 / 决策链长度 / 已有 LookForge 差异化对应能力

### Step 5：反哺决策包（关键步骤 ⭐）
**找调研结果中的"决策包催化剂"**：
- 调研发现的某个事实，能**强化决策紧迫性**吗？
- 例如：发现"湖北盛鸿 ZL202421145712.8 专利 = 滚筒微滤机方向" → 反推出"如签约则演示场景会触发专利侵权问题" → 这恰好是 P0 #21 要解决的问题 → 写进催办飞书，**用真实业务场景强化决策**

## 三、08:00 实证案例（细节可复用）

### 3.1 调研输入
承接 SOP v0.1 §七承诺：「8:00 cron → 加 5 家候选客户的扩展画像(企查查/官网调研)」。

5 家候选：湖北盛鸿 / 中科海 / 海容工业 / 连云港赣榆 / 朱建新。

### 3.2 关键发现
| 客户 | 真实证据 | 优先级调整 |
|---|---|---|
| 湖北盛鸿渔业 | 爱企查主体 + knozall 推荐位 + ZL202421145712.8 实用新型（循环过滤污水净化装置）| **升至 P0-1** |
| 中科海 | 官网 zhongkehai.com + "蟹公寓®"商标 + 海鲜品种高客单价 | **升至 P0-2** |
| 连云港赣榆项目 | 政府采购平台 tgnet.com 公开项目 + 设备清单含"微滤机/蛋白分离器"= HW-001/005 对口 | **保持 P1** |

### 3.3 反哺决策包
**湖北盛鸿已有 ZL202421145712.8 专利（滚筒微滤机方向）** →

推论链：
1. 湖北盛鸿签约 LookForge → 演示滚筒微滤机方案
2. 客户问"这方案是否侵权我的 ZL202421145712.8？" → LookForge 当前答不上来（patent_risk 是 LLM 凭空生成，无真实专利 API）
3. P0 #21「专利占位符接入真实 API」就是为这种场景准备的
4. **结论**：P0 #21 不再是"未来潜在需求"，而是"湖北盛鸿签约前必须解决的问题"

### 3.4 产出文件
- `evolution/2026-09-07_08.md`（9.1KB）：8 节结构（含 5 家画像 + 行业展会 + SOP v0.2 建议 + P0 #21 耦合证据 + 自检 + 下次计划）

## 四、模板（下次 cron 可复用）

| 步骤 | 模板 |
|---|---|
| Step 1 读最近报告 | `ls -lt ~/.hermes/profiles/maodou/evolution/*.md \| head -3` |
| Step 2 识别承接 | 报告里搜"下个 cron\|下一步\|承诺"关键词 |

## 五、与其他 cron auto-evolve 模式的区别

| 模式 | 何时用 | 风险 |
|---|---|---|
| **本模式（客户研究 → 决策包证据）** | 已有 SOP/决策包承诺的下游动作 | 低（不产生代码）|
| 决策包起草（P0 #21 #22 02:00/04:00 已用）| 华哥需要拍板的事项 | 低 |
| SKILL.md 校准（如 commit 39a5e9d8 那种）| 数据一致性回写 | 低 |
| 自主写代码（cron 写代码）| ❌ 待 SOP 拍板授权 | 中-高 |
