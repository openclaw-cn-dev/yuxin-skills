# P2 政策窗口叠加话术升级方法论（v1 → v6）

## 用途

当小宝需要构建"政策窗口紧迫感"销售话术（公众号 / 抖音 / 朋友圈 / 销售面谈）时，按本 skill 的升级链方法论沉淀证据 + 组织话术 + 制定发布期"点缀"决策。

**触发条件**：
- 任何政策类销售文案 / 自媒体内容需要"多省份 + 多品种 + 多资本类型"紧迫感叠加
- 调研捕获新省实证 / 新资本巨头入场 / 新养殖品种落地
- 发布期决策：是否引入最新升级版话术（v5 → v6）？

### 1.2 升级触发条件（满足任一即触发下一档）

- ✅ 新亿元级项目披露
- ✅ 新养殖品种省级官方数据出现
- ✅ 全国/省级官方数据新维度（如设施渔业容积、海水养殖产量）

## § 2 · 同日发布期"点缀"决策原则（v5 → v6 实战沉淀）

### 2.1 决策原则（与 v5 一致）

```
当日发布期 = 已发布内容（公众号 v4）+ 抖音 v2（v4 主结构）+ 朋友圈图卡
v5/v6 升级内容 = 朋友圈图卡 #6/#7 新增首引（17:30-18:30）
完整 v5/v6 升级留待次日中午档抖音 v3（24h 二次确认窗口）
```

### 2.2 决策矩阵

| 载体 | 决策 | 理由 |
|------|------|------|
| 公众号文章（已发布）| ❌ 不替换主结构 | 红线 #18 承诺-兑现 + 失公信力 |
| 抖音 v2（12:00 发布）| ✅ 仅在话术末尾点缀 v5/v6 元素 | 不破坏 v4 主结构 + 风险可控 |
| 朋友圈图卡 #1-#5（15:00-17:00）| ✅ 维持 v4 主结构 | 同上 |
| 朋友圈图卡 #6（17:30）| ✅ v5 新增（山东堃茂 5 源）| 首次引入 v5 的最佳窗口（避开主结构）|
| 朋友圈图卡 #7（18:00）| ✅ v6 新增（江苏 + 四川 8 省实证）| 首次引入 v6 的最佳窗口 |
| 金句 #3（19:30）| ✅ v6 新增（8 省 + 紧迫感 5 倍）| 替换为 v6 升级版金句 |
| 次日中午档抖音 v3 | ✅ 完整 v5/v6 升级版 | 24h 二次确认窗口已就位 + 调研已深化 |

### 2.3 反例（必避免）

- ❌ 当日替换公众号主结构 = 红线 #18 触发 + 失公信力
- ❌ 抖音 v2 直接完整覆盖 v4 主结构 = 风险叠加（v4+v5+v6 同时引入 = 客户认知负担过重）
- ❌ 跳过图卡 #6/#7 直接抖音 v3 = 浪费当日发布期资源
- ❌ 多版本号同日多次升级 SKILL.md = 红线 #20 diff 噪声

## § 3 · 销售方法论 #28 · "全场景 + 多品种"销售核武器

### 3.1 问题与解法

**问题**：客户常问"我们这里适不适合 RAS" / "我们这种品种适不适合 RAS" → 单省单品种实证难说服。

**解法**：把单一省份 + 单一品种实证 → **多省份 + 多品种 + 多地理类型 + 多资本类型**实证 = 任何客户都能找到对应实证。

### 3.2 5 套地理场景话术模板（v6 沉淀）

```
[话术 1 · 沿海客户]
"您是沿海地区？广东（惠州丰茂花草 + 阳江 6.5 倍）+ 江苏连云港 56.5 万 m³（全省第一）
+ 山东堃茂 5 源 + 福建前三 = 沿海 4 省实证"
```

```
[话术 2 · 中部客户]
"您是中部地区？湖北（淡水养殖尾水排放标准 + 7.5 万 m³ 虹鳟）
+ 广西（北海/钦州 70% 钦州无尾水处理）= 中部 2 省实证"
```

```
[话术 3 · 山区客户]
"您是山区？贵州（周总 1.002 亿加州鲈项目）+ 山东堃茂（丘陵地带）
= 山区 2 省实证"
```

```
[话术 4 · 西部内陆客户]
"您是西部内陆？四川成都 25.86 万 m³ + 千亿级目标
+ 云南芒市工厂化循环水 = 西部 2 省实证（陆养海鲜路径已明确）"
```

```
[话术 5 · 多品种实证]
"加州鲈（鲁 + 苏 + 黔）+ 虹鳟（鄂）+ 鳜鱼（京东 5000 吨）
+ 对虾（通威 1 亿 m³ 全国）= 多品种实证 + 双巨头验证"
```

### 3.3 预期效果

| 层面 | 效果 | 量化指标 |
|------|------|---------|

## § 4 · 红线 #19 tier 优化（8/17 中午档实战）

### 4.1 坑 #28 教训回顾（v1.62.12.2 下午档）

- 当前 Hermes `web.extract_backend` = DuckDuckGo (ddgs) search-only
- **不支持 URL 内容提取** · 任何 `web_extract` 调用必然返回 backend 限制错误
- v1.62.12.2 实战：浪费一轮调研时间等 web_extract 失败 + 已知错误信息反复出现

### 4.2 优化决策（v1.62.12.6 中午档）

- ✅ **不要尝试 web_extract，直接 web_search**（吸取坑 #28 教训）
- ✅ web_search 二次确认信息源（搜索结果已含关键摘录可覆盖大部分需求）
- ❌ 反例：反复调用 web_extract 等待奇迹发生（= 浪费时间）
- ❌ 反例：web_extract 失败后改用 plain HTTP curl（= 红线 #19 拦截）

### 4.3 实战案例（v1.62.12.6 中午档）

```
调研需求：捕获 2026 工厂化循环水养殖新省实证
```

| 步骤 | 动作 | 结果 |
|------|------|------|
| 1 | web_search query = "工厂化循环水养殖 2026 新政 农业农村部 水产 8月" | ✅ 命中 5 源（含湖北日报 / 扬子晚报 / 网易等）|
| 2 | web_search query = "通威 工厂化循环水养虾 上市 全国 1000万立方米" | ✅ 命中 5 源（含网易转载 + 中国江苏网）|
| 3 | web_search query = "循环水养殖 2026年8月 浙江 安徽 江西 工厂化 新基地" | ❌ 失败（Brave search timeout）|
| 4 | fallback web_search query = "连云港 海州区 新坝镇 加州鲈 工厂化循环水 5.5万尾 2026年5月" | ✅ 命中扬子晚报（已沉淀）|
| 5 | web_search query = "循环水养殖 2026年8月 浙江 安徽 江西 工厂化 新基地" | ❌ 失败（timeout）|
| 6 | 转向具体省份 web_search query = "通威 工厂化循环水养虾 上市 全国 1000万立方米" | ✅ 命中四川成都千亿级目标（中国江苏网 + 四川日报）|

**关键节省**：未尝试 web_extract = 节省 5-10 分钟调研时间（避免已知 backend 失败轮询）。

### 4.4 红线 #19 决策流程升级

**v1.62.12.1 决策流程**：
```
web_extract（失败立即 fallback）→ web_search → tirith → browser
```

**v1.62.12.6 升级决策流程**（吸取坑 #28 教训）：
```
web_search 直接调用（跳过 web_extract）→ 必要时 browser_navigate 兜底
```
