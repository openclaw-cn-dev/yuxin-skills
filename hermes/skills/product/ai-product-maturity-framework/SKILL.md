# 渔芯自己的 AI · 成熟度框架（8+1 层）

华哥 2026-11-04 定的**正式 roadmap 骨架**：所有「渔芯自己的 AI」产品按此 8+1 层对齐、逐层打分、排优先级。第一载体 = 渔芯知识库，YoooClaw C·ONE 等复用同一骨架。

## 8 层框架（模型只是第 1 层）

| # | 层 | 一句话 | 不做的代价 |
|---|---|---|---|
| 1 | 模型 Model | API 接模型、贴 logo | 只是「别人的 ChatGPT」 |
| 2 | 系统提示词 System Prompt | 知道替谁干活、什么语气 | 推荐对手、乱扯 |
| 3 | 知识库 RAG | 切段→向量→先查再答，引用真规定 | 凭空编数字（500 vs 50） |
| 4 | 工具 MCP | 会办事（退款/工单/通知） | 只是聊天机器人，不是 Agent |
| 5 | 权限 Access | 按角色给权限，用工具前先看是谁 | 越权泄露 |
| 6 | 护栏 Guardrails | 拦提示词注入、过滤输出 | 信里藏一句就全额退款 |
| 7 | 快取+路由 Cache+Router | 省钱，简单题给小模型 | 2000 人同时问，token 账单爆 |
| 8 | 可观测性 Observability | 留痕、提示词存档、改前跑测评 | 答错了没人知道为什么 |

## 第 9 层：自进化（渔芯差异化，抖音没讲）

淘汰 / 整理 / 缺口 / 冲突 / 合成（L0–L4）：草稿隔离、只读源、必引用、可回滚。对应华哥「后期自进化淘汰、不保留映射、全部重新梳理」需求。

## 评估工作流（华哥甩来外部框架/笔记时）

1. **提炼成「层」模型**：一层一句话 + 一句「不做的代价」（让每层有痛感，好打分）
2. **对照真实产品状态打分**——**必须用实测数字，不能拍脑袋**（例：写「hit@5 63.3%」而非「检索还行」）
3. **落盘对照卡** `docs/渔芯AI-8层成熟度对照卡-YYYYMMDD.md`，固定四段：框架 / 现状打分表 / 结论 / roadmap 候选
4. 华哥确认「当 roadmap 骨架」→ 把「下一步」升级为 **P0/P1/P2 阶段**，逐项打勾框 `- [ ]`
5. 存 Mnemosyne（全局），后续任何 AI 产品复用同一骨架，不必重新对齐

## 当前基线（渔芯知识库 0.16.3，第一载体，2026-11-04 实测）

- 1–3 层「读」扎实，但**第 3 层 hit@5 仅 63.3%**（目标 ≥85%）—— 这是根
- 4–5 层：只读不写（仅 kb_search/kb_domains/kb_ask）、无角色级 ACL
- 7 层快取+路由空白；8 层缺「改动前强制跑测评」CI 门禁
- Roadmap：**P0 补根**（hit@5 攻坚 + F-R01 拒答判定收口）→ **P1 会办事**（MCP 写工具 + ACL）→ **P2 省钱可观测**（缓存路由 + CI 门禁）

## Pitfalls

- **打分必须绑定实测数字**。审查曾发现 hit@5 三个数字打架（80% / 100% / 63%），根因是评测口径放水——「关键词出现」即判对。收口口径要落到 `expected_doc_ids`（期望文档 id 是否命中），禁再用「关键词出现」判分。
- **华哥简短指令要最小化落地**（「落盘」「当 roadmap 骨架」）——只做对应的一步，别脑补成多层铁律/大架构。华哥会反向纠正过度架构化。
- **外部框架笔记不盲信**：抖音/AI 初稿里的数字与「故事」要交叉核查、绑定公司实测数据后再落盘。
