# 研究项目立项 SOP（华哥「新增加调研项目」标准路径）

> v1.1.0（2026-10-07）实证重写：单日连续立项 7 个项目（行业知识文章/行业论文/行业专利/目标市场开拓/水产技术学习/环保和谐共存/RAS设备出海）+ GLM 额度超限日亲自执行首轮 + 「滚动 3 轮」21 轮全部完成。

## 1. 触发条件

- 华哥消息含「新增加调研项目 / 新增调研项目」→ 立项全流程（§2）
- 华哥消息含「以上项目持续滚动调研 N 轮」→ 批量执行模式（§6）
- 学习助手额度超限 → 降级执行模式（§5）
- 华哥消息含「停止调研 / 已进入开发状态 / 停调研」→ 结项流程（§7）

## 2. 标准流程（单项目约 10 分钟，6 步）

> v1.2.1（2026-10-15）：补 Step 5 汇报规范实证（双产出定位范式、轮数默认值申报、「不做」清单）。「研-如何配置合适的电脑」立项实证。

### Step 0 · 查重与边界扫描（必做）
- `cronjob list`：已有覆盖的不新建（华哥 8-22 省 token 铁律）
- `ls 01-开发中/`：扫兄弟项目 → 总纲显式写「与兄弟项目的边界」+「联动纪律」。措辞范式：「79 号=产品本地化数据地基；本项目=市场作战档案」「那边按市场逐国建档（需求侧），这边按设备品类横切（供给侧）」；同数字引用注明出处，不重复造数

### Step 1 · 项目目录 + 总纲 README
路径 `6-产品研发/渔芯独角兽/01-开发中/研-{项目名}/`：

```
README.md            # 总纲（cron 自驱动的唯一依据，最重要）
02-华哥原始指令.md    # 华哥原话逐字存档 + 落地说明
01-研究报告/          # 轮换报告 NN-{方向名}.md
02-xxx/               # 按形态：文章成稿/论文孵化/交底书草稿(保密)/政策雷达/学习大纲+笔记
00-市场队列.md        # 仅队列驱动型
```

总纲 README 必含 5 件（缺一 cron 断驱）：
1. **一句话定位**
2. **与兄弟项目的边界 + 联动纪律**
3. **方向骨架**：编号方向表（10±2 个），可分 A/B/C 层
4. **目录说明**
5. **进度登记表**：表头固定 `| 日期 | 方向 | 产物 | 关键结论一句 |`——cron 每轮读它定方向、写完追加一行。**登记表 = 单一事实来源**

**豆包/AI 初稿存档**（华哥工作流：外部 AI 出初稿→玉芬综合整理）：华哥转来的豆包/外部 AI 初稿存入项目目录（如 `03-外部初稿/`），**显式标注「外部 AI 初稿，未经交叉核查」**；采用其内容前必须绑定公司实际数据交叉核查，不盲信。

### Step 2 · 轮换 cron
- profile=zhenglishi，model=GLM-5.3-flash/glm，deliver=local，enabled_toolsets=["web","terminal","file","search"]
- **cron 的 model 必须显式传 provider**：`model={"model": "GLM-5.3-flash", "provider": "glm"}`，别只传 `{"model": "..."}`（省略 provider 会钉成 default 会话当前主 provider，额度切换日会错配成 DeepSeek，见 Pitfall 6）
- **错峰调度**：多 cron 分钟数错开（实证 :00/:10/:20/:30/:40/:50 × 9/15/21 时）
- cron prompt 六要素：①身份+项目一句话 ②**第一步读总纲 README 进度登记表**（自驱动，不写死方向）③本轮任务+报告路径与命名 ④报告必含结构（现状盘点≥3 源交叉/渔芯可执行结论/遗留项移交下轮）⑤数据铁律（官方一手优先/≥2 源交叉/标数据年份/查不到写「暂未查到」不凑数）⑥收尾更新登记表 + **「不动兄弟项目、不动 cron 配置」**
- 特殊纪律双写：项目总纲写一次、cron prompt 再写一次（专利交底书保密、论文「涉专利点暂缓成文」等）

### Step 3 · 原始指令存档（原话逐字 + 落地说明）

### Step 4 · Mnemosyne 登记（remember 项目全貌 + task_progress 状态）

### Step 5 · 汇报华哥：表格化（项目/产出/频率）+ 落地清单 + 联动设计 + 首轮起跑时间；授权模式下直接定案不追问

汇报三件实证（2026-10-15「配置合适电脑」项目过审零追问）：
- **双产出定位范式**：立项汇报给产出定「对内+对外」双身份（例：对内=渔芯自用采购指南回应真实痛点，对外=方法论内容资产），并标注重点候选方向及锚定场景——华哥据此快速判断项目价值。
- **未指定轮数=默认申报不追问**：华哥没说轮数时，总纲写成「N 方向各一轮后回卷深化」，汇报尾注「默认设定可随时改」一句即可，不作为问题抛回（授权模式：小默认自己拿主意）。
- **敏感产出预设闸门**：产出含采购/预算/签约类建议时，总纲和汇报都写明「产出对比表等华哥拍板，不擅自定采购」（对应华哥硬约束：大额采购需拍板）。

## 3. 三种 cron 形态

| 形态 | 适用 | 机制 |
|---|---|---|
| **方向轮换型**（默认） | 有 N 个方向 | 每轮读登记表 → 顺序推进下一方向，N 轮后回卷挑薄弱深化 |
| **市场队列驱动型** | 「指定市场类」持续扩展 | `00-市场队列.md`：华哥指定→入队→每市场 M 维建档（状态/进度 N/M）→档案完成转持续追踪（增量扫描写入追踪日志）；华哥一句话入队即生效 |
| **单文件综合报告型** | 「持续更新的综合报告」 | 主报告单文件多模块（M1-M7），cron 每轮扫增量→直接编辑对应模块→更新日志追加行；模块内嵌「下轮更新计划」滚动改写 |

## 4. 不需要做的事

- **不用改「📊 研项目每日进度汇总(华哥)」cron**（39bd34537174，21:30）：动态读各 研- 项目 README 登记表，新项目自动纳入
- 不用为每个项目建 heartbeat；不抄兄弟项目结论进总纲（引用路径+出处即可）

## 5. GLM 额度超限降级执行

信号：cron 大量 last_status=error / 华哥告知套餐超了 → 华哥说「今天的调研工作你亲自执行」时**直接自己跑**：web_search 采数据（每主题 2-3 query）→ 写报告 → 更新登记表，注明「玉芬亲自执行（GLM 额度受限日）」+「cron 自下轮按方向 N 续推」→ 恢复后无缝续推不重不漏。付费墙数字（GVR 精确规模等）宁缺毋滥维持定性口径。

## 6. 「滚动 N 轮」批量执行模式

「以上项目持续滚动调研 N 轮」→ 全部项目 × N 轮：
- 每项目按登记表顺序推进 N 个方向/单元，每轮产出真实文件（报告 1.5-3KB 简明体量）
- **⚠️ delegate_task 600s 上限实证（2026-10-07）**：多项目打包给子代理（每轮 5-10 次 web_search+write）2/2 超时且未写盘产物丢失 → 批量轮次**直接自己顺序执行**；确需子代理时收窄到单项目、限产物数量
- 完成后统一 patch 各 README 登记表 + find 统计产物数核验 + 表格化汇报

## 7. 停调研转开发（结项）SOP

**触发**：华哥说「已经进入开发状态的项目的停止调研任务」/「停止调研」/「只停调研、开发/积累继续」。

**Step 1 · 判断「已进入开发状态」的项目（依据优先级，2026-10-12 实证）**
1. `01-开发中/项目开发就绪度评估-20261005.md`：T1「立即启动开发」/ T2「待华哥拍板」/ T3「继续采集」三级（这是华哥拍板的权威分级）
2. 各项目 `项目开发启动书_*.md` / `开发评估.md`（T1 项目才产出）
3. 开发产物目录：`03-开发/`、`04-平台开发/`、`06-大脑架构/`（说明已动工）
→ 定位其轮换调研 cron：`cronjob list` 找「{项目简称}-轮换调研」类 name（profile=zhenglishi）

**Step 2 · 分两类操作（关键区分）**
- **纯调研 cron**（prompt 只做轮换调研）→ `cronjob action=pause`。**可逆，不 remove**——华哥说「停止」= pause 即可，彻底删要等他明说。
- **开发/积累型 cron**（prompt 已含「开发优先」或「资料积累」步骤）→ **不能简单 pause**，要 `cronjob action=update` 改 prompt **去掉调研步骤、保留开发/积累**，再 `action=resume`。华哥说「只停调研、开发/积累继续」就是这个意思——例：AI智能大脑 cron 从「开发优先+穿插调研」删掉穿插调研；网安平台 cron 从「资料积累+轮换调研报告」删掉轮换报告。

**Step 3 · 汇报边界**：表格化（项目 / cron id / 原频率 / 判断依据）；把「T2 待拍板」项目和「属性特殊」的 cron（已转开发优先/已降月度单扫）**单独列出请华哥确认**，不擅自扩大范围到 T2。

**Pitfall · jobs.json 中文字段是 unicode 转义**：`~/.hermes/cron/jobs.json` 的 `name`/`prompt` 是 `\uXXXX` ASCII 转义存储，`search_files`/`grep` 搜中文（如「调研」）**搜不到**。查 cron 中文名用 `cronjob list`（工具会解码），或搜转义码（「研」=`u7814`）；终端批量统计 state/last_status/profile/429 分布直接 `python3 -c "import json,collections; ..."` 解析 jobs.json 最省事。

## 8. Pitfalls

1. **profile 会话 skill_view 404 共享根 skill**：available_skills 列出但 skill_view not found（文件在 `/Users/hua/.hermes/skills/` 共享根，profile 只解析自己目录）→ 不要干等，用 skill_manage create/edit 直达共享根文件操作；按共享正本铁律不另存 profile 副本
2. **cron prompt 写死方向**：与登记表漂移；永远「先读登记表再定方向」
3. **登记表结论列太长**：一句（≤40 字）+关键数字，细节在报告文件
4. **跨项目时序纪律**：可专利技术方案先专利后论文/文章公开——内容类项目总纲互相引用；发现可专利化空白时报告只写「已转交专利项目评估」不展开细节
5. **登记表行数即进度**：滚动轮完成后务必 patch 登记表，否则 cron 下轮会重复已做方向
6. **cron model 参数省 provider 会 pin 错 provider**（2026-10-11 实证）：`cronjob create` 的 `model` 若只传 `{"model": "GLM-5.3-flash"}` 不传 provider，工具会把 provider 钉成**当前 default 会话的主 provider**，而非目标 profile（zhenglishi）的默认 provider——当 default 因额度切换到 DeepSeek 时生成「GLM-5.3-flash + deepseek-cn」错配组合，首跑即报错。修正：显式传 `{"model": "GLM-5.3-flash", "provider": "glm"}`（与存量研究 cron 一致）；建完用 `cronjob list` 核 job 的 provider 字段应为 `glm`。
