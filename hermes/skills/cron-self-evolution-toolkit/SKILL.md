## 1.7 🆕 P-34 静默 HOME 劫持近失事故证据(2026-09-24 小宝 cron 02 时档首例 · 后续 10 时档黑豆 round 68 第 17 次命中实证 + 首次日间命中证据见 `references/***SECRET***.md`)

> 📌 **触发条件**(三连):① 首调 `heartbeat_check.py <profile>` 时 stdout 空 + exit 0 + 实际 $HOME 被劫持到其他 profile = **agent 完全无感劫持,继续推进整个 evolution 流程**(浪费 1 次工具调用配额 + 整个 cron 在劫持态运行)
> 📌 **关键差异**:`cron-home-hijack-bypass §7` 已记录 11 次劫持实测,**全部为显式 FileNotFoundError**。本档实证**第 12 例 = 静默 exit 0 变种**——更隐蔽,**协议层「先 echo $HOME」提醒不够强**,必须升级为 prompt 模板硬约束
> 🎯 **核心产出**:三道防线 SOP(prompt 模板硬约束 + 劫持态显式标注 + wrapper 层联动)

### 1.7.1 与既有劫持实测对比(11 例 → 12 例)

| 维度 | §7 已知 11 例(全部) | **P-34 静默变种(本档)** |
|---|---|---|
| 报错类型 | 显式 FileNotFoundError | **stdout 空 + exit 0(脚本吞 stderr)** |
| 劫持识别时间 | 首调即识别 | **推迟到第 4 次调用** |
| agent 主观感受 | 立刻察觉异常 | **误判为「正常无任务」进入 evolution** |
| 协议层提醒有效性 | 高(看到报错即停手) | **低(没报错就不知道要自检)** |
| 风险等级 | 中 | **高(整个 cron 在劫持态运行)** |

### 1.7.2 三道防线 SOP

| # | 防线 | 实现层 | 状态 |
|---|---|---|---|
| 1 | **prompt 模板硬约束** | xiaobao-evolution-protocol §0 v1.31 升级 | ⏳ 待玉芬过审 |
| 2 | **劫持态显式标注** | evolution 报告 §0 段新增「静默劫持」变种标注格式 | ✅ 本档 §3.2 已定义 |
| 3 | **wrapper 层联动** | `cron-launch.sh` 写入 `/tmp/cron_home_check.txt`,agent 首调 `cat` 自检 | 📌 华哥/B 团队任务 |

### 1.7.3 强制纪律

```
✅ DO:prompt 首行 = echo $HOME 三确认(无条件,先于任何业务命令)
✅ DO:劫持态检测后,evolution 报告 §0 段显式标注
✅ DO:劫持态下全程绝对路径 /Users/hua/...,无 ~/、无 $HOME/、无 Path.home()
❌ DON'T:不要相信「heartbeat_check.py 空 stdout」= 无任务(可能 = 静默劫持)
❌ DON'T:不要把 echo $HOME 写在 if 块内(失效 = 默认跳过)
❌ DON'T:不要在劫持态下用 skill_view 加载本档(可能命中双名歧义,改用 read_file 绝对路径)
```

### 1.7.4 不触发的反向保险

| 场景 | 应改走 |
