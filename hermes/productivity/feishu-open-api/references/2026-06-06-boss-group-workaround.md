# 老板总控群 — 无 `im:chat.members:write_only` 时的"话事人"架构

**适用场景**：老大想建一个跨部门总控群，但缺拉机器人进群的权限，**等不及**管理员审批。

**核心思路**：用**一个**已有的应用（建议用销售小成 = 跟客户最近的 agent）作为老板的"话事人"进总控群，**其他 Agent 不进总控群**，但仍在自己部门群活跃。**老板 → 话事人 → 其他 Agent** 通过"话事人转述"完成跨部门协作。

## 拓扑图

```
老板 → RAS-老板总控 (1 个群，1 个机器人)
         └─ 💰 销售小成 (话事人)
              ↓ 老板说 "让小研做个方案"
              ↓
         💬 销售小成把任务转写到 RAS-研发部-测试
              ↓
         🔬 研发小研在自己的群里响应
              ↓
         📝 销售小成把研发小研的回复转回老板总控群
```

## 实现步骤

### 1. 建总控群（用销售小成 app）

```python
# 同原 deploy recipe Step 2，但 name/description 强调"话事人"角色
data = {
    "name": "RAS-老板总控",
    "description": "老板总控驾驶舱 | 5 Agent 协同 | @销售小成 (话事人) 一键触发",
    "chat_mode": "group",
    "chat_type": "private"
}
# 用 sales token 建 → sales 自动成为群成员（不需要任何额外权限）
```

### 2. 不拉其他 Agent 进群

跳过 Step 4 — 没有 `im:chat.members:write_only` 就不强求。

### 3. 4 个 Agent 在自己群活跃

- 销售群、研发群、生产群、推广群**早已建好**（4 个独立私群）
- 每个群里**只有一个 Agent**（该群的主人）
- 老板总控群里**只有销售小成**

### 4. 话事人转发协议（重点）

老板发"@小研 蛋白分离器怎么选型？"，销售小成作为话事人要：

```python
# a. 在老板总控群 ack 收到指令
post_message(sales_token, boss_chat_id, "收到！小弟转给小研 ~")

# b. 模拟老板身份把指令发到研发群
#    （这里"老板身份" = 销售小成用销售小成 token 发的消息，
#     研发小研会看到是"销售"转过来的，可以理解是话事人代发）
post_message(sales_token, rd_chat_id, "老板问：蛋白分离器怎么选型？@研发小研")

# c. 等研发小研在自己群响应后（轮询 rd_chat_id 拉新消息）
# d. 把研发小研的回复转回老板总控群
post_message(sales_token, boss_chat_id, "🔬 研发小研回复：<研发小研的回复>")
```

## 话事人协议的简化版（推荐）

**对于日常运营**，老板根本不需要"转发"机制，直接：

1. **老板在销售群问 → 销售小成回**（最常见路径，~70% 指令）
2. **老板说"@小研 xxx"** → 销售小成把消息**复制**发到研发群（"老板问：xxx"）
3. **研发小研在研发群回** → 销售小成**轮询**研发群（30s 一次）→ 把回复**复制**回老板总控群

## 适用 / 不适用

| 场景 | 适用话事人架构？ |
|---|---|
| 老板主要问销售/询盘/客户问题 | ✅ **完美**（话事人就是销售，0 转发）|
| 老板问技术 → 转研发 | ✅ 适用（多一次转发，30s 延迟）|
| 老板问生产 → 转生产 | ✅ 适用 |
| 老板问推广 → 转推广 | ✅ 适用 |
| 跨部门紧急协作（销售+研发同时响应）| ❌ 不适用（要等前一个回完才能转下一个）|
| 100% 实时性要求 | ❌ 不适用（改去申请权限）|

## 何时升级到完整 4 Agent 总控群

当以下任一条件满足时，让老大去开权限升级：

1. **老板 1 天要发 5+ 条跨部门指令**（话事人转发的延迟开始痛了）
2. **2 个以上部门 Agent 经常被同时 @**（要等串行转发）
3. **业务进入稳态运营**（不再是一问一答，是并行多 agent 协作）

升级方法：去 https://open.feishu.cn/app/{app_id}/auth 申请 `im:chat` + `im:chat.members:write_only`，管理员审批后**重跑原 deploy recipe Step 4 即可**。
