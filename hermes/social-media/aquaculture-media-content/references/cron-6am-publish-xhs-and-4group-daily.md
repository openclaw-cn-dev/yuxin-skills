```
  [✗] 推送失败
[V4] 推送模式：🏢 公司群 - 海大集团
  [✗] 推送失败
```

**根因**：`feishu_rag_v4.py` 的 `send_to_feishu()` 用：
```python
subprocess.run(["hermes", "send", "feishu", message], capture_output=True, timeout=30)
```
**returncode != 0** → 4 群全失败。

**正确路径**（按 `daily-cron-architecture` skill 的多群 fan-out fallback）：
- ❌ **不要** 修 `feishu_rag_v4.py` 改 send_to_feishu —— 文档已说硬编码 home channel 不可用
- ✅ **直接** final response 就是 delivery（cron 模式由系统推送给老大）
- ✅ final response 里**完整写出 4 群日报内容**（不是只写摘要），让老大可以复制粘贴到 4 群
- ⏳ 长期修复：需要实现 `feishu_rag_v5.py` 用 fan-out 4 个真实 chat_id（参考 `daily-cron-architecture` 的飞书多群 fan-out 段）

## 3.5. 「老大需要决策的事」4 大常见问题（**2026-06-22-6/23 实战模式**）

**4 群日报末尾**必须列出老大**还没修**的问题（不要只报喜不报忧）：

1. **cron prompt 过期** —— prompt 写"今天 6/12"，实际 6/22+ —— 建议 `hermes cron edit` 加动态日期
2. **V 编号缺口** —— 跳号（V9-V11 没生成）—— 建议**不补**，跳号继续
3. **数据回填缺失** —— `posts_log.csv` 不存在 / 是占位 —— 老大回填 V{今天} 时顺便建 csv
4. **日报合并版漏发** —— 6/19-6/21 daily 目录有分群文件但没合并 —— 6 点 cron 从哪天开始没跑

**铁律**：
- ❌ **不要"修了再说"** —— 老大不一定修，但**每次都列**直到真改
- ❌ **不要"自己悄悄修"** —— prompt 改动要老大确认
- ✅ **用 P0/P1 标签**：P0 = 阻塞运营，P1 = 优化建议

## 5. 关键经验（踩过的坑）

| 坑 | 教训 | 复发日期 |
|---|---|---|
| `笔记V*.md` 假设存在 | **必须每次 `ls` 验证**，缺失立刻生成 | 6/14, 6/22, 6/23 |
| `posts_log.csv` 5 行 6/10 数据当真实反馈 | **是占位/示例**，V1-V7 周轮走完前不要用于排序 | 6/14, 6/23（**6/23 实测文件根本不存在**）|
| `feishu_rag_v4.py --mode daily` 推送成功 | **4 群全失败**，`subprocess.run(["hermes", "send", "feishu"])` 不工作 | 6/14, 6/22, 6/23 |
| **cron prompt 日期过期 11 天没人改** | **Step 0 必跑 date 自检**，过期 > 7 天日报列 P0 | 6/15 (3天), 6/22 (10天), 6/23 (11天) |
| **V 编号跳号**（V9-V11 缺） | **跳号不补**，直接 V12 继续 | 6/22, 6/23 |
| **日报只报喜不报忧** | **末尾"老大需要决策"段必列 4 大问题** | 6/22, 6/23 强化 |
| 标题字数超过 30 字 | **小红书 18-25 字**，超 30 字直接划走 | - |
| 在 22 点后发小红书 | **避免深夜**，V1 实际 22:46 算准点（19-22 段），00:57 太晚流量低 | - |
| 数据回填区不标 `_待填_` | **必须明确占位**，避免老大以为是真实数据 | - |
| 4 群日报按月循环不刷新 | **每周主题固定**（周几=啥内容），跨年也一样 | - |
