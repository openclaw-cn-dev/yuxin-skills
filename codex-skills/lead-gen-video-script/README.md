# Lead Gen Video Script

一套面向咨询、培训、企业服务及其他高客单业务的中文获客型短视频 Skill。

它不会拿到选题后立即生成一篇“看起来正确”的文案，而是先检查目标客户、痛点场景、问题根因、解决机制和可信证据是否充分，再通过追问补齐关键信息，最终生成能够筛选客户、建立专业信任并承接转化的短视频脚本。

## 它解决什么问题

普通 AI 脚本经常出现这些问题：

- 目标人群只有“老板”“创业者”等宽泛标签；
- 痛点停留在“获客难”“转化低”等抽象概念；
- 根因只是换一种说法重复症状；
- 解决方案只有步骤，没有解释为什么有效；
- 案例只展示成绩，无法证明核心观点；
- 结尾突然要求关注、私信或购买，与前文需求脱节。

这个 Skill 优先优化精准线索、专业信任和自然转化，而不是默认追求最大播放量。

## 核心逻辑

Skill 使用九个环节检查获客说服链：

```text
人群触发
  ↓
痛点场景
  ↓
问题代价
  ↓
根因诊断
  ↓
核心主张
  ↓
解决机制
  ↓
可信证据
  ↓
适用边界
  ↓
行动承接
```

这九项是逻辑检查点，不是要求脚本机械地写成九段。

## 主要能力

### 从零创作

根据业务、产品和选题，分轮补充信息，先生成脚本策略卡，再生成完整口播稿。

### 诊断现稿

识别现有脚本最大的转化断点，区分人群、场景、根因、方案、证据和 CTA 问题。

### 质量评分

按照八个维度进行审核：

| 维度 | 权重 |
|---|---:|
| 人群精准度 | 15 |
| 场景具体度 | 10 |
| 需求紧迫度 | 10 |
| 根因洞察 | 15 |
| 核心主张 | 10 |
| 解决机制 | 15 |
| 证据可信度 | 15 |
| 转化承接 | 10 |

### 生成精准钩子

在人群、场景和核心主张明确后，从具体场景、问题代价、诊断反差或真实结果切入，避免用无关猎奇吸引错误流量。

## 安装

### 方式一：克隆到 Codex Skills 目录

```bash
git clone https://github.com/xintu1314/lead-gen-video-script.git ~/.codex/skills/lead-gen-video-script
```

重新打开 Codex 会话后即可使用。

### 方式二：下载 ZIP

1. 在 GitHub 仓库页面选择 **Code → Download ZIP**；
2. 解压并将目录命名为 `lead-gen-video-script`；
3. 移动到 `~/.codex/skills/`；
4. 重新打开 Codex 会话。

最终目录应类似：

```text
~/.codex/skills/lead-gen-video-script/
├── SKILL.md
├── agents/
│   └── openai.yaml
└── references/
    ├── logic-framework.md
    ├── evaluation-rubric.md
    └── examples.md
```

## 使用方法

### 1. 从零生成获客脚本

```text
使用 $lead-gen-video-script 进入深度模式。

先检查我的信息是否足够，每轮最多问我 3 个问题。
先输出脚本策略卡，我确认后再生成最终口播稿。

我的产品是：
目标客户是：
这次想讲的选题是：
```

### 2. 诊断已有脚本

```text
使用 $lead-gen-video-script，诊断下面这条脚本的获客逻辑。

先不要改写，告诉我最大的转化断点、缺失信息和修复顺序。

[粘贴脚本]
```

### 3. 发布前审核

```text
使用 $lead-gen-video-script 给这条脚本评分。

保留我的核心观点和说话方式，只修改真正影响获客转化的部分。

[粘贴脚本]
```

### 4. 只生成钩子

```text
使用 $lead-gen-video-script，根据已经确认的人群、场景和核心主张，
分别从场景、代价、诊断反差和结果四个方向生成开头。
不要使用与目标客户无关的猎奇悬念。
```

## 脚本策略卡

正式生成口播稿前，Skill 会优先梳理：

```text
目标客户：
触发场景：
表层问题与代价：
用户原有判断：
真正根因：
核心主张：
解决机制：
可信证据：
适用边界：
下一步行动：
```

如果关键信息不足，Skill 会继续追问，而不是擅自补造事实。

## 适用场景

- 咨询与顾问服务；
- 企业培训；
- B2B 产品与服务；
- 专业服务机构；
- 高客单知识产品；
- 需要通过内容建立专业信任的个人或团队。

## 不适用场景

- 单纯追求泛流量和娱乐传播；
- 普通 AI 工具教程；
- 剧情、段子和娱乐脚本；
- 产品和交付尚未成立，却希望只靠文案解决商业问题；
- 要求 AI 虚构客户、收入、结果或个人经历。

## 项目结构

- `SKILL.md`：触发边界、工作模式、追问流程和输出规则；
- `references/logic-framework.md`：九段获客逻辑和信息合格标准；
- `references/evaluation-rubric.md`：100 分评分体系；
- `references/examples.md`：常见问题与修改示例；
- `agents/openai.yaml`：Codex 中的展示信息和默认调用提示。

## 使用原则

- AI 负责整理信息和检查逻辑，不替创作者发明行业经验；
- 所有收入、客户、案例和结果必须来自真实材料；
- 解决方案必须对应前面诊断出的根因；
- 案例必须证明核心主张，而不是装饰内容；
- CTA 应当成为用户当前需求的自然下一步；
- 高播放量不是默认目标，也不等于获客质量高。

提交案例时请删除客户姓名、联系方式、商业机密及其他敏感信息。
