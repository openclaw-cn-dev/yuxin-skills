# 原文排版：一字不改（长图、卡片、公众号共用）

原文路径（原文长图、原文卡片、公众号排版）设计的对象是版式，不是文字：每一句原文按原顺序只出现一次，不摘要、不润色、不改标点、不补标题、不抽金句。生成图固定为 0，只呈现原稿自带的图片。译文（`article.zh.md`）和改写稿的文章形态（`rewrite.md`）也按同样的规则排——对排版来说，它们就是"原文"。

## 允许与禁止

| 属于排版（允许） | 属于改稿（禁止） |
|---|---|
| 原稿的标题、整段粗体小标题 → 标题层级 | 摘要、润色、纠错、改标点、同义改写 |
| 粗体、斜体、引用、列表、代码、表格 → 对应样式 | 删节、合并段落、调换顺序 |
| 改字号、字重、颜色、留白；在行与行之间分页、分卡 | 抽一句做题记、金句或结尾大字 |
| 段内换行保留为换行 | 原稿没有的标题、导语、小结、过渡句 |
| 页眉页脚的来源、作者、页码、品牌（不算正文） | 把来源说明、免责声明写进正文 |

原文里确实有错别字、要删的推广段落时：原文路径不能动它。要么告诉用户，由用户改 `article.md`；要么改走改写路径。

## 它怎么保证一字不差

1. **锁定来源**：记录文章的 SHA-256，渲染结束再算一次，变了就报错。
2. **原文块账本**（`ledger.json`）：每个可见文本块（段落、标题、列表项、表格单元、引用、代码、图注）一个编号，顺序即阅读顺序。
3. **解析覆盖**：账本拼起来的文字必须等于原文去掉 Markdown 符号后的文字，防止解析器漏段。
4. **页面读回**：浏览器里逐块读 `textContent`，必须与账本逐字相同；还检查块数、顺序、重复、嵌套、正文区有没有不属于任何原文块的字、视觉顺序有没有倒退。卡片里一段跨两张卡时，两截按顺序拼起来比对。公众号里换行写成 `<br>`，比对时不计换行。
5. 改一个字、调一次序、漏一块、重复一块，都会失败（✗ 全文校验）。不能靠目测放行。

## 交付时报告

原文块数与全文校验结果（"45 / 45 块逐字一致"）、来源、生成图 0 张；分成了几张图或几张卡。
