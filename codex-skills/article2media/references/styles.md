# 风格（主题）

主题只是一个 CSS 文件：`engine/themes/<名称>.css`。它主要定义变量（颜色、字体、圆角），版式结构由 `engine/layouts/` 负责。
所以**同一份 content.json、同一篇文章可以用任何主题渲染**，长图、卡片、公众号都适用，换风格不用改内容。

```bash
node <long-image>/scripts/long.mjs --list                          # 列出所有主题（任何渲染脚本都支持 --list）
node <long-image>/scripts/long.mjs content.json                    # 用 content.json 里的 "theme"
node <long-image>/scripts/long.mjs content.json --theme notebook   # 指定主题（覆盖 content.json）
node <long-image>/scripts/long.mjs content.json --theme quiet,bento   # 多个主题，分目录输出
node <long-image>/scripts/long.mjs content.json --theme all        # 全部主推主题（12 套）
node <wechat-layout>/scripts/wechat.mjs article.md --theme quiet   # 文章同理
```

## 内置主题

主推 12 套。每套除了配色和字体，还有**自己的封面**（标题处理、装饰、底部导语区的样子各不相同）和整页金句卡的画法，在缩略图里就能分辨。

| 名称 | 气质 | 封面的样子 | 首选场景（与下方选择指南一致） |
|---|---|---|---|
| `editorial` | 商业杂志：暖白纸面、宋体、沉稳主色、米色图卡 | 杂志刊头：顶部色条、角标、双线下的导语 | 商业、创业、营销、行业分析、人物观点；作者自己的经历与复盘 |
| `swiss` | 瑞士极简：纯白、黑体、粗黑分割线、红黑双色 | 网格海报：红色方块、黑色通栏 | 数据、研究、财经、政策等严肃议题；设计、艺术、展览、摄影 |
| `quiet` | 静线：暖纸底、暖黑字、只有一种暗朱红、细线与大留白 | 一个细线圆、线上的导语，不铺色 | 哲思、单一观念、书与论文的深度解读；情绪、成长、心理、人文随笔 |

## 选择指南（用户没指定主题时，由你来选）

按顺序走三步，**每一步都只产出一个结果**（有发布数据时还有一个只做平手裁决的第 4 步）。

**第 1 步：用户有没有明确倾向？** 只看**用户对风格提的要求**，文章里出现的词不算（比如文章讲"波尔多红怎么搭"，不等于用户要波尔多红的风格）。有就直接用，不再往下走。
- "深色""暗黑"→ `midnight`；"简约""干净""白""安静""读书杂志""静线"→ `quiet`；"手写""笔记感""手帐""备忘录"→ `notebook`；"醒目""大字报""波普""复古海报"→ `brutal`；"杂志""高级"→ `editorial`；"多巴胺""彩色""活泼""可爱"→ `dopamine`。
- "苹果风""发布会""便当格"→ `bento`；"Y2K""Y3K""千禧""镭射""液态铬""甜酷""像素"→ `y2k`；"电影感""胶片""宽银幕"→ `film`；"国潮""中国红""喜庆"→ `guochao`；"新中式""国风""古风""山水""水墨"→ `shanshui`；"瑞士""极简""红黑"→ `swiss`。
- 用户点名了某个经典主题（`cloud`、`earth`、`memo`、`glass`、`collage`、`pop`、`pixel`、`prosperity`、`riso`），就用它，不替换。
- 用户有自己的品牌色或固定风格时，以用户为准。

**第 2 步：按题材定首选。** 先用一句话说出**文章主要在讲什么**，再在下表里找**最贴切**的一行。题材看全文，不看标题里出现了什么词：标题里有 "AI"，但通篇在讲商业模式，就算"商业"；文章顺带提到某个节日、某座城市，不等于它在讲节日或文旅。
只有两行**同样贴切**时，才取靠上的那行。

| 文章主要在讲 | 首选 |
|---|---|
| 节庆与民俗（传统节日、节气习俗、非遗手艺本身）、国货国潮品牌、城市文化与文旅活动：热闹、当代的中国元素 | `guochao` |
| 古典历史人物与典故、诗词国学、茶与器物、东方美学：安静、文人气的中国元素 | `shanshui` |
| 电影、剧集、纪录片与影视评论；人物传记、人物特写、深度访谈（围绕一个具体人物展开，不论他在哪个行业，非遗匠人、企业家都算） | `film` |
| 技术向的 AI、编程、开发者工具：给动手搭建的人看的用法、搭法、原理、工作流 | `midnight` |
| 产品或工具（包括 AI 工具）的测评、横评、对比、盘点；年度总结；给普通用户看的 AI 应用、手机数码与智能汽车等新品、发布会、科技趋势（不讲技术细节） | `bento` |
| 美妆、明星娱乐、追星、二次元；游戏、互联网文化与怀旧 | `y2k` |
| 自媒体运营、涨粉、创作者收益、副业与个人变现（哪怕是作者讲自己的经历）；品牌营销案例、广告创意、流行文化现象 | `brutal` |
| 好物种草与购物清单（含双十一等大促）、美食探店、家居、时尚穿搭、送礼清单；健康、养生、运动、饮食、睡眠；日常生活记录、vlog | `dopamine` |
| 数据、研究、财经、政策等严肃议题；设计、艺术、展览、摄影 | `swiss` |
| 商业、创业、营销、行业；从业者或名人对这些话题的观点；作者自己的经历与复盘、职场故事、旅行游记 | `editorial` |
| 以笔记形式整理一本书、一门课或一种学习方法（这一行看形式：读书笔记就用它，不管书讲什么）；实用技巧合集：职场技巧、效率方法、生活小技巧；校园、手作与兴趣爱好 | `notebook` |
| 哲学、思想、单一观念的深度解读；书与论文的论证；情绪、成长、心理、人文随笔（安静、需要留白的长文） | `quiet` |

都不像时用 `editorial`。

**第 3 步：只在出卡片、且发到小红书 / IG / 抖音图文这类信息流时，按下面两条调整一次**（从上往下，命中一条就停）：
1. 第 2 步选的是 `editorial`、`swiss`、`quiet`、`notebook`、`midnight`、`bento` 之一（偏阅读型的主题），而文章的**形式**是教程、攻略、避坑、清单，改用 `brutal`：大字报在信息流里最抓眼。判断依据只看**标题和一级标题 / 整体组织方式**：标题里有"攻略""教程""清单""全流程""实操""步骤""手把手""保姆级""避坑""从 0 到 1"，或"N 个 / N 件 / N 条 / N 招"这类数量清单，或者一级标题就是"第 1 步、第 2 步…""Lv.0、Lv.1…"。正文某一节里出现步骤列表不算；一级标题只是"睡眠、饮食、运动"这类主题分块也不算；"实测""横评""对比"是测评，不算教程；整体是观点文章或评论的，也不算。拿不准时做这个判断：**只读标题和一级标题，读者能不能按顺序照着做下去？** 能（第 1 步、第 2 步……）就是教程；读到的是一个人的做法、经历、观点或经验总结（"我的创业复盘""Lessons learned"），就不是。其他主题本身就是为信息流设计的，保持不变。
2. 首选是 `midnight`，改用 `bento`：深色封面在浅色信息流里容易显脏，撞色白卡更清楚。（`film` 的深色是风格本身，不改。）

其他情况（长图、公众号、X，或没命中这两条）**保持第 2 步的首选**。

**第 4 步（可选）：有发布数据时，只用来在两个同样合适的选项里定一个。** `article2media-out/stats-report.md` 存在时读它的「分平台」一节（没有就跳过这一步；想更新就运行 `node <article2media>/scripts/stats.mjs report`）：
- 只看**目标平台**那张表里 **n ≥ 5** 的主题 / 封面版式；标着"样本不足"的行一律不用，哪怕数字很好看。
- 只在前三步留下两个同样贴切的候选时用：第 2 步里两行同样贴切、你本来打算出两版比较，或封面在两种 `cover.style` 之间拿不准（比如 `hook` 和 `number` 都成立）。这时选收藏率 / 互动率中位数更高的那个。
- **不能推翻**用户明确的偏好（第 1 步），也不能因为某个主题数据好，就把它用到题材不合的文章上：数据比较的是这个账号发过的帖子，差别里混着选题和发布时机。
- 用了就在交付时说出来，带上样本量，例如："brutal 和 bento 都合适，选了 brutal：你在小红书发过的 6 条 brutal 互动率中位数 8.9%，bento 5 条是 6.1%。样本不大，仅作参考。"没用到就不提。

选定后把 `"theme": "<名称>"` 写进 content.json（只排文章时，用 `--theme` 传给脚本）。第 3 步改过主题时（哪怕这次只出卡片），也把两种场景分开写，以后用同一份 content.json 出长图、公众号还能用第 2 步的主题；写成 `"theme": {"long": "midnight", "cards": "brutal", "wechat": "quiet"}`。交付时用一句话说明理由，例如："选了 notebook：这是一篇学习方法拆解，格纹手帐风更像一份能收藏的笔记。"

一篇文章拿不准时，可以用 `--theme 甲,乙` 出两版，看 overview 挑一个。但最后只交付你推荐的那版，另一版作为备选提一句。

## 新建主题

复制一个现有主题改变量即可；要让它进入主推列表（`--list`、`--theme all`、测试矩阵），把名字加进 `engine/themes/catalog.json` 的 `main`。第一行注释的格式是 `/* 名称 | 气质描述；适合：…… */`，`--list` 和选择时都会读它。
主题 CSS 在版式 CSS **之后**加载，所以主题里写的结构覆盖规则会生效。

```css
/* warm | 暖色手帐：米黄纸、霞鹜文楷、橙绿双色；适合生活记录 */
@import url('https://fonts.googleapis.com/css2?family=...&display=block');   /* 可选：网络字体 */
:root {
  --font-head: '…', serif;      /* 标题字体 */
  --font-body: '…', serif;      /* 正文字体 */
  --font-label: …;              /* 可选：小标签（编号、"图 1A"）的字体 */
  --bg: #…;                     /* 页面底色 */
  --ink: #…;                    /* 正文色 */
  --ink-strong: #…;             /* 可选：加粗文字的颜色 */
  --muted: #…;                  /* 次要文字 */
  --rule: #…;                   /* 分割线 */
  --rule-soft: #…;              /* 浅分割线 */
  --fig-bg: #…;                 /* 图卡底色 */
  --card: #…;                   /* 白卡片（面板里的卡片、图内方框） */
  --on-acc: #…;                 /* 主色底上的文字颜色 */
  --radius: 2px; --radius-sm: 2px;
  --panel-mix: 12%;             /* 面板底色 = 主色按这个比例混进底色 */
  --guard-bg: #…; --guard-ink: #…; --guard-muted: #…;   /* 清单里深色"护栏"卡 */
  --accent-1: #…;               /* 主色序列，各节依次轮换，数量不限 */
  --accent-2: #…;
}
```

可选变量：
- `--acc-text-override`、`--acc-line-override`：主色太浅（比如黄色）时，用它们把"主色文字"和"主色细线"统一改成深色。
- 排版：`--fs-title`、`--fs-h2`、`--fs-body`、`--w-title`、`--w-h2`、`--h2-ink`。
- 线条与阴影：`--sec-rule`、`--fig-border`、`--panel-border`、`--card-border`、`--card-shadow`、`--warn`、`--guard-x`。

注意：
- 主色要和 `--bg`、`--card` 有足够对比度，因为它会用于小标题和高亮方框的底色。
- 深色主题里，`--on-acc` 通常要设成深色。
- 字体要选覆盖简体中文的字体，并在字体栈末尾留系统字体作回退（如 `'PingFang SC'`、`'Songti SC'`）。
- 换了展示字体后，渲染一行"回图国圆品器噩"这类内外多层框的字看一眼：有的字体（比如站酷小薇）会把"回"画成实心黑块，版面检查发现不了。
- 新主题做好后，用 `examples/gallery.json` 把长图和 `--ratio 3:4` 卡片各渲染一遍，检查所有图表组件。
