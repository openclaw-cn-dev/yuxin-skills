# 漫画：让机制在画面里动起来

黑白漫画分镜。**生成图**负责让角色、场景、动作和结果可见；**HTML** 负责把旁白、对白、音效字、概念名和来源写准确——图里一个字都不画。同时输出一张长漫画和一组小红书 3:4 卡片。

需要出图能力（Codex CLI 登录即可，或 OpenAI / Gemini 付费 key）。没有时直接告诉用户做不了漫画，并给出可选替代（长图、白板）。

```bash
node ${CLAUDE_SKILL_DIR}/scripts/comic.mjs check <目录>/comic.json
node ${CLAUDE_SKILL_DIR}/scripts/comic.mjs make  <目录>/comic.json      # 出图（约 1–1.5 分钟一格，3 格并行）+ 排版
node ${CLAUDE_SKILL_DIR}/scripts/comic.mjs render <目录>/comic.json --theme quiet   # 只重排（分格已缓存）
```

## 1. 先把讲解变成认知因果拍点

找一个能承载核心机制的**最小案例**，同一角色、道具、空间贯穿全篇（漫画的理解力来自前后可比较）。分镜按这条链生长：

```
最小案例 → 零号模型运行（旧做法真的试一次）→ 一个可观察的缺口
        → 一个概念补位 → 同案重跑（同样的场景，结果变了）→ 下一个缺口……
        → 整体回收 → （必要时）边界：改一个条件，看哪里先失效
```

- 格数由认知跳跃决定，不凑格：删掉某格后读者仍能完成同样的理解，这格就该删。
- 每格只承担**一个可见动作或一个可比较结果**；概念先以动作显示必要性，术语在旁白里后到。
- 每格三问：去掉它会少一次必要的认知变化吗？与前后格能直接比较吗？只看画面能看懂谁做了什么、什么变了吗？

## 2. comic.json

```jsonc
{
  "title": "主标题（可用 **关键词**）", "cover_title": "卡片封面标题（2–3 行）", "kicker": "小标题", "subtitle": "一句话说清这组漫画讲什么",
  "source": "article.md",               // 用来生成署名
  "anchor": "p01",                      // 锚点格：先生成，作为其他格的角色与画风参考
  "bible": {
    "character": "固定角色：年龄、发型、眼镜、服装、关键道具（英文更稳）",
    "setting": "空间连续性：房间、灯光",
    "style": "画风族：静谧电影线描 / 精密机械线稿 / 墨韵留白 / 高对比暗黑 / 粗线动势（写成可观察的描述）"
  },
  "panels": [
    { "id": "p01", "role": "最小案例|零号模型|缺口|补位|重跑|回收|边界", "size": "wide|half|tall",
      "scene": "写给出图模型：具体的可见动作和结果（英文更稳，不写对白和文字）",
      "narration": "旁白 ≤ 60 字：点明缺口、给概念命名、校准证据",
      "bubbles": [{ "text": "对白 ≤ 18 字", "x": 70, "y": 58, "tail": "left|right|none" }],
      "sfx": "音效字", "sfx_x": 70, "sfx_y": 60, "caption": "可选：格下说明 / 来源" }
  ],
  "recap_title": "末张卡片标题", "recap": ["三条要点"], "closing": "收束句"
}
```

- `wide` 占整行（3:2），`half` 两格一行（1:1），`tall` 竖格（2:3）；half 尽量成对。
- 对白和旁白的位置用百分比；渲染会检查它们有没有超出分格。

## 3. 画面纪律

- 生成提示词自动加上：黑白漫画、纸白背景、角色锚点、单一可读动作、因果结果、网点与墨块控制；统一负向约束：不画对白泡、格线、旁白框、音效字、页码、任何文字、Logo、水印、彩色、照片感、多余角色，关键主体不裁切。
- 锚点格通过后再批量生成；其余格把锚点图作为参考图，角色和画风才会一致。每格失败最多重试一次，仍失败就停止并说明。
- 人物用泛指的虚构角色，按原文写对性别和年龄，不画真实人物。成品页脚注明「画面由 AI 生成 · 人物为示意」。

## 4. 审片与交付

- 先看 `comic/comic.png`（或 `review/slice-*.jpg`），再看 `comic/overview.jpg`（卡片）：角色是否连续、每格动作能否独立读懂、文字有没有压住脸和手。
- 交付：长漫画与卡片路径、格数与因果链（如"最小案例 → 零号模型 → 缺口 → 补位 → 重跑 → 回收"）、生成图张数与服务商、署名。
