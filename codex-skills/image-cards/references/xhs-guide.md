# 总结卡片指南（小红书 3:4 / Instagram 4:5 / 方图 1:1 / 竖屏 9:16）

`cards.mjs <content.json> --ratio <比例>` 把改写稿渲染成一组固定比例的卡片（宽 1080），并生成一份发帖文案 `caption.md`。这份指南讲 content.json 里卡片专用字段怎么写；原文卡片（输入是文章）不需要这些字段，见 `original-cards.md`。

| 比例 | 尺寸 | 典型平台 | 单篇上限 | 每张能放下的内容 |
|---|---|---|---|---|
| `3:4` | 1080×1440 | 小红书、抖音图文 | 18 张 | 标准：正文约 90 字 + 一张图 |
| `4:5` | 1080×1350 | Instagram | 20 张 | 比 3:4 略少 |
| `1:1` | 1080×1080 | 方图、朋友圈 | 20 张 | 最紧：正文 ≤ 50 字效果才好，否则图会被缩小或省略 |
| `9:16` | 1080×1920 | Stories、竖屏 | 20 张 | 最宽裕 |
不写任何额外字段也能出图；下面这些字段用来把它从"能用"改到"好用"。

## 卡片结构（自动生成）

| 顺序 | 卡片 | 内容来源 |
|---|---|---|
| 1 | 封面 | `cover`，6 种版式（见下）；没有就用 `title` + 第一页 `intro`，按大字版式出 |
| 2… | 每节一张 | label、heading、`card.text`（缺省用第一段）、一张图、takeaway；也可以整张做成金句、大数字或整页图（`card.style`） |
| … | 清单 2–3 张 | checklist 节的阶段自动分到几张卡里，"护栏"放在最后一张 |
| 末张 | 全文要点 | 最后一页 `closing` + 每节 takeaway 列表 + 来源 + 收藏提示 |

小红书一篇最多 18 张图，超出时会报错。**建议控制在 10–16 张**：用 `"mode": "skip"` 去掉次要的节。

**空间是自动用满的**：图按实际画出来的内容放大（不会悬在一个空框中间）；卡片还有余量时，先放大字号，再把这一节的 `bullets`（前 3 条）补进来，剩下的均匀分到各块之间。所以不用为了"填满"去加字。

卡片放不下（或图会被缩得太小）时，渲染会按 要点 → 图注 → 数据面板 → 正文 → 图 的顺序**自动省略**，并在版面检查里提示「已自动省略：……」。看到这条提示时，应该主动缩短 `card.text` 或改用 `split`，而不是接受省略。

## 1. 封面：最重要的一张

封面决定用户会不会点开。先定**版式**（`cover.style`），再写字段。不写 `style` 时：有封面插画用 `image`，写了 `number` 用 `number`，写了 `versus` 用 `versus`，其余用 `hook`。

| `style` | 样子 | 什么时候用 | 需要的字段 |
|---|---|---|---|
| `hook`（默认） | 标题放到最大，底部一条主色带里放导语和最多 4 条短要点 | 标题本身就是钩子：结果、反常识、一句判断 | `title`，可选 `subtitle`、`points` |
| `number` | 一个巨大的数字，下面一句解释，再是标题 | 全文有一个压得住场的数字（413 个文件、4 小时、73%） | `number: {value, unit, label}` |
| `versus` | 左右两块对比，右边那块是答案（主色） | 文章的核心是 A 和 B 的反差（记 413 个文件 / 记 10 个） | `versus: {left, right}`，每边 `{label, value, note}` |
| `quote` | 大引号 + 一句话 + 署名 | 核心是原作者的一句论断 | `title` 写那句话，可选 `by` |
| `image` | 插画通栏，标题在下面 | 用户要了封面插画 | `illustration` |
| `toc` | 标题 + "这组图讲了"目录 | 工具书式的合集，读者按目录找内容 | 可选 `points` |

```jsonc
"cover": {
  "style": "hook",
  "title": "一个人\n就是一支\n**创意团队**",   // 2–3 行，每行 ≤ 10 字；用 **…** 标出 1 个关键词
  "kicker": "Dan Koe 长文拆解 · 15 张图",       // 可选，标题上方的小字
  "subtitle": "2027 年最赚钱的 AI 生意，不是做工具，而是替品牌抓住注意力。",  // ≤ 60 字，说清"这组图能给你什么"
  "points": ["为什么最值钱", "团队怎么搭", "第一个客户"],  // hook 显示前 4 条、每条 ≤ 12 字；toc 显示 3–6 条、每条 ≤ 16 字
  "number": { "value": "413", "unit": "个文件", "label": "什么都记的模型，只拿到 1 枚徽章" },   // number 版式
  "versus": { "left":  { "label": "什么都记", "value": "413", "note": "个文件，1 枚徽章" },
              "right": { "label": "只记关键", "value": "10",  "note": "个文件，4 枚徽章" } },      // versus 版式
  "by": "Dan Koe",   // quote 版式的署名，缺省用原文作者
  "summary": "…",   // 可选，末张"全文要点"的大字总结；缺省用最后一页的 closing
  "cta": "收藏这组图，开始搭你的内容系统"  // 可选，末张底部的按钮文字
}
```

- 数字和对比值要短：`number.value` ≤ 5 个字符，`versus` 的 `value` ≤ 4 个字符；单位写进 `unit` / `note`。数字必须是原文里的。
- 封面标题要比长图标题**更短、更有冲突感**。不要照搬原文标题。
- **人称**：别人的文章不写成"我"（"我的面包店一年翻了三倍" ✗，"一家社区面包店，一年营业额翻三倍" ✓），封面、小红书标题、备选标题都一样，见 `../../article-rewrite/references/writing-guide.md` 第 2.5 节。
- 好的写法：给出结果（"一个人就是一支创意团队"）、给出数字（"5 个阶段拿下第一个客户"）、点出反常识（"最赚钱的技能不是写代码"）。
- 不要夸大：不写"月入十万""保姆级""全网最全"。

## 2. 每张卡：一张卡只讲一件事

手机上一屏只看得到一张卡，所以卡片正文比长图更短。在节里加 `card` 字段：

```jsonc
"card": {
  "mode": "single",        // single（默认）| split（拆成两张）| skip（不出这张卡）
  "text": "…",             // 卡片正文，≤ 90 字；缺省用 paragraphs[0]
  "bullets": ["…", "…"],   // 可选，≤ 3 条、每条 ≤ 26 字；放在图下面
  "figure": 1,             // 用哪张图：0（默认）、1，或 "none"
  "panel": false,          // single 模式下要不要把数据面板也放进来（通常放不下）
  "style": "quote",        // 可选，整页卡型：quote | number | image（见下）
  "quote": "…",            // quote 卡的句子，缺省用这一节的 takeaway；≤ 26 字，会在逗号处断行
  "number": { "value": "73%", "unit": "", "label": "只用搜索时的正确率" }   // number 卡
}
```

**整页卡型：给一组图做出节奏。** 十几张卡如果张张都是"标题 + 正文 + 图 + 金句"，读者划到第 5 张就疲劳了。每 3–4 张安排一张整页卡：

| `card.style` | 样子 | 适合哪一节 |
|---|---|---|
| `quote` | 整张主色底，只有一句大字 | 这一节的结论本身就是一句能被截图转发的话 |
| `number` | 一个巨大的数字 + 一句解释，下面是正文和金句 | 这一节靠一个数字立住 |
| `image` | 图占满整张卡（插画或照片会铺满；图表则放到最大，不带正文） | 这一节的图比文字更有说服力 |

内容卡达到 6 张而一张整页卡都没有时，校验会提示节奏偏平。整页卡只用在真有那句话、那个数字的节上，不要为了凑节奏硬造。

- **大数字要回答这一节的标题**：标题讲"每周只发 3 条"，大数字就该是"3 条"，不是同一节里另一个"1.2 万粉"。标题里有数字而大数字不是它时，校验会提示。
- 数量：每 3–4 张内容卡一张整页卡（7 张内容卡 → 2 张）。少了校验会提示。
- **整页卡会替换这一节的卡片内容**（图、面板都不上卡）。这一节的图和面板也重要时，写 `"card": {"mode": "split", "style": "quote"}`：第一张是整页卡，第二张是这一节正常的卡。挑整页卡时优先选内容本来就靠一句话、一个数字立住的节，或者和别的节有重复的节。

**一张卡只放一张图**：默认放这一节的原文配图（有的话），否则放 `figures[0]`；`card.figure` 可以指定。第二张图和数据面板不会出现在单张卡上（长图里都有），想让它们上卡片就用 `"mode": "split"`，或 `"panel": true` 把面板放进来。

什么时候写：
- **第一段只是铺垫、要点在第二段**：写 `text`，把要点提前。
- **第二张图更直观**（比如有数字的柱状图）：`"figure": 1`。
- **这一节的面板很有价值**（原话提示词、对照表）：`"mode": "split"`。第一张放正文和图 A，第二张放图 B 和面板。
- **这一节对小红书读者不重要**（工具安装、背景铺垫）：`"mode": "skip"`。
- 卡片超出时，按以下顺序处理：缩短 `text` → 去掉 `bullets` → 用 `split`。

## 2.5 封面多版本、轻量形态、品牌包

**封面多版本（拿去比效果）。** 封面决定点击，值得多出几版让用户挑，或分开发布对比：

```bash
node ${CLAUDE_SKILL_DIR}/scripts/cards.mjs <目录>/content.json --covers     # → <主题>-3x4-covers/cover-01-hook.png …、overview.jpg
```

- 不写 `cover.alts` 时，同一个标题按能用的版式各出一张（hook、quote、toc，有数据时加 number、versus、image）。
- 想比较**不同的钩子**时写 `cover.alts`：每项只写要替换的字段，其余沿用 `cover`。最多 4 个，挑差别大的写（结果型、数字型、反常识型）。

```jsonc
"cover": { "title": "一个人\n就是一支\n**创意团队**", "…": "…",
  "alts": [
    { "title": "最赚钱的技能\n**不是写代码**" },
    { "style": "number", "number": { "value": "5", "unit": "个阶段", "label": "拿下第一个客户" } }
  ] }
```

用户选定后，把选中的那版写回 `cover`，再出整组。发布后的数据用 `article2media` 的 `stats.mjs` 记下来（见该 skill），以后选版式有依据。

**轻量形态（`--form`）。** 同一份 content.json 还能切出三种更轻的图，适合高频更新，或给整组卡片引流：

| `--form` | 产出 | 内容来源 |
|---|---|---|
| `quotes` | 金句图：每句一张，整张主色底 | `quotes`（`["…", {"text": "…", "by": "…"}]`），没写就用每节的 `takeaway` |
| `onepage` | 一页看完：标题 + 最多 9 条要点，一张图讲完 | `onepage.points`（`[{"title": "…", "text": "…"}]`），没写就用每节的标题和 `takeaway` |
| `qa` | 问答卡：对话气泡，问题在右、回答在左，自动分张 | `qa`（`[{"q": "问题 ≤ 24 字", "a": "回答 ≤ 70 字"}]`），**必须写** |

```bash
node ${CLAUDE_SKILL_DIR}/scripts/cards.mjs <目录>/content.json --form onepage                # → <主题>-3x4-onepage/onepage-01.png
node ${CLAUDE_SKILL_DIR}/scripts/cards.mjs <目录>/content.json --form quotes --ratio 1:1     # → <主题>-1x1-quotes/quote-01.png …
node ${CLAUDE_SKILL_DIR}/scripts/cards.mjs <目录>/content.json --form qa                     # → <主题>-3x4-qa/qa-01.png …
```

- 问答是**读者会问的问题**加原文给出的回答，用"他说"转述；不要编原文没有的回答。4–8 组为宜。
- 这三种形态不出发帖文案；金句图和一页看完可以直接配 `xhs.caption`。

**品牌包（`brand.json`）。** 让读者认得出"这是谁的图"。字段都可选，查找顺序见 `../../article2media/references/pipeline.md` 第 4 节：

```jsonc
{ "name": "你的名字", "handle": "@you", "series": "实战手册",
  "avatar": "avatar.png",                 // 头像，路径相对 brand.json；出现在封面左上角、末张品牌栏、长图页脚
  "tagline": "每周拆一篇好文章",            // 末张品牌栏的一行介绍
  "follow": "关注 @you，每周一篇",          // 末张按钮文字（cover.cta 优先）
  "accent": "#FF5A1F",                    // 品牌色：替换主题的第一个主色（封面、末张、第一节）
  "issue": 12 }                           // 期号，显示为"第 12 期"；content.json 的 "issue" 或 --issue 13 覆盖它
```

用户第一次说"加上我的头像 / 用我的品牌色 / 做成系列"时，帮他在 `~/.config/article2media/brand.json` 建好这份文件；期号每篇不同，写进 content.json 的 `issue`。

## 3. 发帖文案：`xhs` 字段

```jsonc
"xhs": {
  "title": "2027最赚钱的AI生意：一人创意团队",   // ≤ 20 个字符（平台上限；字母、空格也按 1 个算，保守起见少用空格）
  "caption": "……",                            // ≤ 1000 字，建议 300–600 字
  "tags": ["AI创业", "个人品牌", "内容创作", "Dan Koe", "副业"]   // 5–8 个，不用写 #（caption.md 里脚本会自动加上）
}
```

正文的写法：
1. **第一句是钩子**：用一个问题或一个反常识的判断，不要用"今天给大家分享"开头。
2. 写 2–3 句，说明这组图解决什么问题、适合谁看。
3. 列出 3–5 条要点，每条一行，可以用 ①②③ 或"→"。
4. **注明原作者**："内容整理自 Dan Koe 的 X 长文《…》"。小红书正文里的外链一般不能点击，写清作者和标题就够了。
5. 最后一句引导互动：问一个读者能回答的问题，或者提醒收藏。
6. 正文里可以少量用 emoji 分段，但图片里不要用 emoji。

标签的选法：1–2 个大类（AI工具、个人成长）+ 2–3 个具体主题（Claude Code、个人品牌）+ 1–2 个人群或场景（打工人、副业）。

## 4. 检查

渲染会输出 `overview.jpg`（所有卡片的总览）。先看总览，再打开有问题的单张卡：
- 封面在缩略图大小下，能不能一眼看清标题？
- 有没有哪张卡太空，或者文字挤成一团？
- 图有没有被缩得太小？QA 会提示"图只放大到 x 倍"。
- 卡片顺序读下来，像不像一个完整的故事？
